# AI Symptom Chat — Backend

Express + TypeScript API powering the AI Symptom Chat portfolio project.
Uses [Groq](https://console.groq.com) (free tier) for AI inference.

> ⚠️ **This is not a medical device and does not provide diagnosis.**
> It is a portfolio demo. Always consult a licensed doctor for real
> health concerns. No real patient data should ever be sent to this API.

## Stack
- Node.js + Express + TypeScript
- Zod (request validation)
- express-rate-limit (protects the free Groq quota)
- Groq API (`llama-3.3-70b-versatile`)

## Setup (Windows / VS Code)

1. Unzip this folder and open it in VS Code (`File → Open Folder`, pick the
   folder that directly contains `package.json`).
2. Open the integrated terminal (`` Ctrl + ` ``) and run:
   ```powershell
   npm install
   ```
3. A `.env` file is **already included** in this zip with a placeholder key.
   Open it directly in VS Code:
   ```powershell
   code .env
   ```
   Replace `your_groq_api_key_here` with a real key from
   [console.groq.com](https://console.groq.com) (Sign up → API Keys → Create
   Key). No quotes, no spaces around `=`. Save the file.
4. Start the server:
   ```powershell
   npm run dev
   ```
   You should see `Server running on port 3001`.
5. **Important:** if you edit `.env` while the server is already running,
   restart it (`Ctrl+C`, then `npm run dev` again) — environment variables
   are only loaded once at startup.

## Setup (macOS/Linux)
```bash
npm install
npm run dev
```
(the `.env` file is already present — just edit the key value before starting)

Server runs at `http://localhost:3001`.

## ⚠️ API key security
Never commit `.env` to git or paste your real key into a chat, doc, or
screenshot. `.gitignore` already excludes `.env` from version control. If a
key is ever exposed, delete it in the Groq console and generate a new one
immediately — old keys remain valid until manually revoked.

## Testing it works
```powershell
# Health check
Invoke-RestMethod -Uri "http://localhost:3001/api/health"

# Chat endpoint
Invoke-RestMethod -Uri "http://localhost:3001/api/chat" -Method Post -ContentType "application/json" -Body '{"message": "I have had a mild headache since yesterday"}'
```
A successful chat response includes `reply`, `urgency`, and `disclaimer` fields.

## Endpoints

### `GET /api/health`
Returns `{ status: "ok", timestamp }`. Used for uptime monitoring.

### `POST /api/chat` (non-streaming)
```json
// Request
{
  "message": "I've had a headache for 2 days",
  "history": [
    { "role": "user", "content": "..." },
    { "role": "assistant", "content": "..." }
  ],
  "language": "en"
}
```
`language` is optional (defaults to `"en"`) and accepts `"en"`, `"ar"`, or
`"ur"`. When set, the AI is instructed to reply in that language — this
powers the frontend's multi-language chat support.
```json
// Response
{
  "reply": "...",
  "urgency": "self-care" | "see-a-doctor-soon" | "seek-urgent-care" | "emergency" | "unclear",
  "disclaimer": "This is not a medical diagnosis..."
}
```

### `POST /api/chat/stream` (streaming — used by the frontend)
Same request shape as `/api/chat`. Responds with Server-Sent Events:
```
data: {"delta": "Mild"}

data: {"delta": " headaches"}

data: {"meta": {"urgency": "self-care", "disclaimer": "..."}}

data: [DONE]
```
The reply text streams token-by-token in real time (via Groq's `stream: true`).
Structured JSON can't be usefully parsed mid-stream, so urgency/disclaimer are
generated by a fast, separate, non-streamed classification call once the full
reply text is known — that's why the `meta` event arrives just after the last
`delta`, not interleaved with it.

## Safety design
- The system prompt (`src/prompts/systemPrompt.ts`) explicitly forbids
  diagnosis and medication advice, and forces a disclaimer field.
- `groqService.ts` adds a **server-side safety net**: if the model ever
  omits the disclaimer or urgency field, the backend fills it in before
  the response reaches the client.
- Emergency-sounding symptoms are instructed to map to `urgency: "emergency"`
  with a message to contact emergency services — but this is a best-effort
  AI classification, not a guaranteed safety system, and must not be relied
  upon in a real emergency.

## Deployment (all free tier)
- Backend: [Render](https://render.com) free web service
- Set `GROQ_API_KEY` and `ALLOWED_ORIGINS` in Render's environment variables
- Free tier spins down after inactivity — first request after idle may take
  10–20s (cold start). Consider a free [UptimeRobot](https://uptimerobot.com)
  ping on `/api/health` to reduce this.
